# Channel deployment map

These are deliberately chosen production canvases, not claims about current platform upload limits. Inspect the actual composer preview before publishing; platform crops, compression and placement rules change. No post is published by this package.

| Channel | Default asset | Editorial approach | Keep in view |
| --- | --- | --- | --- |
| X / Twitter | wide 1280 x 640; square 1080 x 1080 | One claim per image; lead with a product action or a specific developer problem | Headline, mark and one visual; put links and caveats in the post |
| Medium | video 1280 x 720 or wide; concept figures in article | Strong editorial cover, then diagrams and actual product evidence | Useful alt text and captions; large code belongs in the article |
| Reddit | square or wide product-story | Explain the problem, demonstrate the implementation, disclose project affiliation | Match each community's rules; avoid unsubstantiated comparison cards |
| GitHub | github-social 1280 x 640 in the parent creative folder; wide README figures | Show what the project does and how to run it | Developer-preview and compatibility boundaries |
| YouTube | video 1280 x 720 thumbnail; 16:9 motion bumper | Make the subject clear at thumbnail scale; keep technical details in the video | Large type, one focal graphic, clean lower-right area for duration UI |
| Vertical video | story 1080 x 1920 | Use the main headline and animation as a cover or chapter plate | Keep critical content in the central area; test interface overlays in the destination app |
| Technical media | video or wide SVG/PNG; product captures with provenance | Supply an editorial kit: cover, diagram, screenshot, concise caption and source links | Separate conceptual diagrams from measured product behavior |

## Placement rules

- Use `launch` for general introduction, `feature` for a specific capability, `code` for an API excerpt, `explainer` for architecture, `carousel` for a sequential tour and `release` for an actual release note.
- `release` ships with developer-preview copy, not a fabricated version number. Supply the real change, evidence and date before announcing a release.
- The five-slide carousel is ordered and uses consistent dimensions. Do not rearrange it into a claim about automatic authorization or universal recovery.
- For press handoff, include the PNG, SVG, caption, capture date and provenance. Do not send private logs or credential-bearing exports.
- The repository URL is `https://github.com/NexusFox88/Haxegon`. The displayed product name is Hexagon.
- Platform-native alt text is required; use the asset index as a starting point and describe the purpose of the final image.
