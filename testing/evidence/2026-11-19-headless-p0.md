## Implemented contract

- Shared Agent/direct Session `identity`, `instructions`, `context` schema, limits and initialization digest; historical `agent_revision` selection and immutable Session snapshots. Inline behavior overrides on a saved Agent are rejected.
- Context file references resolve only within the authenticated tenant and Session; missing files, changed hashes, invalid UTF-8 and oversized input fail before Run acceptance. Background enters user-level reference data, not the stable instruction channel.
- Native instruction adapters for Pi/OpenCode/Codex/Hermes/OpenClaw/Claude Code; custom JSON opt-in protocol. Aider/DeepSeek behavior initialization explicitly unsupported. Registration does not fabricate cloud verification.
- `origin` is caller-supplied correlation only. Trusted `execution_identity` is derived from authenticated bindings. Duplicate input+origin is idempotent within tenant/Session; busy sessions retain existing `session_busy` behavior.
- Console Agent editor, Playground, initialization detail/JSON, generated Python/TS/REST and snapshot reuse carry the same behavior fields. Paused Sessions expose continuation without requiring a manual wake operation.
- Existing approvals, broker, OAuth, reconciliation, event persistence, artifacts and serverless lifecycle reused. No new workflow engine, memory service or LLM Gateway.
- Model HTTP status/transport receipts support stable failed-Run error classification without storing upstream content or credentials. HTTP 200 stream errors are not guessed from status.

## Recovery defects found and fixed

1. Modal gRPC transport reads lowercase proxy variables. The deployment environment now sets upper/lowercase consistently (while retaining explicit proxy precedence and local bypass). A read-only diagnostic failed with gRPC unavailable before this change and reached the same restored Sandbox with lowercase proxy variables.
2. After an ambiguous Runtime launch, the platform previously only polled health forever. Recovery now checks health, then probes the daemon's existing advisory lock. Only a free lock permits relaunch through the same lock-protected launcher; held/unknown lock does not relaunch. No existing Run invocation is replayed. This recovered the same Modal second Run rather than creating a replacement Session.
3. Runtime transport, deployment proxy and worker recovery tests passed 29 checks across 3 files (`.local/headless-launch-recovery-tests.log`). Initialization/schema regression passed 12 checks across 2 files (`.local/headless-schema-regression.log`).

Two temporary acceptance workers used the normal durable leases/connector paths to avoid provider delays blocking unrelated acceptance. They were stopped before deploying the recovery fixes, then restarted for the final matrix. Their final teardown is recorded below. The normal control plane remains the product service.
