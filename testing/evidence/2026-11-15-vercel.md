# Vercel Sandbox acceptance

## Private transport

Official SDK 4.0.0 is pinned. Vercel command logs expose text, so `vercel-transport.ts` requests base64 frames from the shared Python stdio/TCP relay and reconstructs binary bytes in the control plane. The command receives only a loopback port and helper source. Provider credentials remain in per-connection SDK calls. The instance exposes no public routes. Stdin writes await provider acknowledgement; output honors stream drain; incomplete or invalid frames fail the transport.

`NODE_USE_ENV_PROXY=1 HEXAGON_VERCEL_TRANSPORT=1 npx tsx tooling/probe-vercel.ts` passed at 09:42:46–09:42:54 UTC. Private journal `.local/evidence/vercel-hexagon-b1794d2f-fe19-4e0d-b59a-99b9577a266f.json` confirms creation, Node/Python execution, 256 KiB binary file roundtrip and HTTP delivery with both Content-Length and EOF framing, independent application authentication (401 without the bearer), zero public routes and absence-confirmed deletion.

The local transport regression runs the real Python relay against a real TCP server, deliberately fragments text log output, and verifies exact 256 KiB HTTP bytes and release. The existing raw-stdio relay tests still pass.

## Connector and expiry

`VercelConnector` implements exact-name create/reconciliation, inspection, absence-confirmed deletion, bounded foreground/background commands, files and private HTTP. Configuration requires project ID, team ID and vCPU count. It creates nonpersistent instances and explicitly refuses to call execution APIs on stopped/persistent resources, preventing implicit SDK restart. Unsupported allowlists fail before creation. Provider 404 alone means absence; auth and transport errors propagate as uncertainty.

`NODE_USE_ENV_PROXY=1 HEXAGON_SANDBOX=vercel npx tsx tooling/smoke-managed-expiry.ts` passed at 09:45:17–09:46:51 UTC. Journal `.local/evidence/vercel-91b1a547-5f50-4eb6-a682-2be70f74d653.json` records an actual 4096 MiB resource, file roundtrip, Runtime protocol 1 readiness, anonymous 401, natural passage of the 90-second deadline, managed Session closure and confirmed provider deletion. This exercises Hexagon's persisted deadline enforcement; it is not a provider-native-expiry-only claim.
