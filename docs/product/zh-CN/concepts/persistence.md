# 工作区、对话、产物与持久化边界

“任务有状态”包含多种数据，它们存放在不同位置，随生命周期变化的方式也不同。选择保留策略时，先说明需要保留的究竟是文件、对话、运行记录，还是进程内存。

## 数据在哪里

| 数据 | 主要位置 | 用途 |
| --- | --- | --- |
| Session / Run、事件、初始化快照 | 控制平面 PostgreSQL | 查询、恢复观察、审计 |
| 初始上传文件 | 控制平面保存输入，执行时准备到 Sandbox | 建立工作区 |
| Agent 修改中的工作区 | 云 Sandbox 的受管理目录 | 连续项目工作 |
| Harness 对话状态 | Harness 管理的 Session 文件 / 原生会话标识 | 多轮上下文 |
| 导出 Artifact | 当前实现存于 PostgreSQL | 独立于云资源的交付快照 |
| 后台服务与内存 | 云环境中的运行进程 | 预览、临时计算、连接 |

## 生命周期保留表

| 动作 | 运行记录 / 导出产物 | 工作区 / 对话 | 进程 / 内存 |
| --- | --- | --- | --- |
| 客户端断开 | 继续保留 | 不因此删除 | 不因此取消 |
| 正常 Run 完成 | 保存结果和导出快照 | 为下一轮保留 | 不能从 Run 终态推断所有后台服务状态 |
| 计划内空闲转换 | 控制平面记录保留 | 按 Provider/Harness 策略恢复 | 可能保留、重启或丢失 |
| Runtime 故障 | 已持久记录仍可调查 | 需要按中断 / 不可达分类 | 不承诺安全自动恢复 |
| Session close | 历史与导出产物保留 | 不再承诺原云工作区访问 | 回收对应资源 |
| 数据库或密钥丢失 | 需要一致备份恢复 | 云工作区不替代控制平面备份 | 进程存在不能重建全部控制记录 |

## 文件留存不等于 Artifact

Agent 在项目目录写了文件，只能说明工作区有该文件。需要交付和关闭后下载的内容应写入 Run 产物目录，并核对导出列表、大小和 hash。每个 Run 的导出是独立快照，第二轮同名文件不会改写第一轮产物。

同样，文件保持不能单独证明 Harness 对话恢复。验证多轮时分别检查一个明确文件内容和一个前轮对话事实。临时目录不属于统一保证，例如 Agent37 的 `/tmp` 不在恢复保留范围。

## 为应用选择保留方式

继续编辑项目：保持 Session 并验证空闲恢复组合。交付一个结果：下载 Artifact 或由应用保存受控副本。长期归档：管理数据库容量、备份和应用自身保留政策，不能把当前保留行为解释成无限期 SLA。需要运行服务：管理进程与预览授权的生命周期，不能仅保存预览 URL。
