# 适用场景与产品边界

当你的应用需要把 Agent 作为可观察、可继续、可恢复的后台工作来运行时，Hexagon 提供 Session、Run 和云执行资源的共同管理层。

## 常见场景

| 场景 | 输入与结果 | 需要关注 |
| --- | --- | --- |
| 应用内项目修改 | 上传代码和需求，得到修改后的文件、测试结果与预览 | 文件权限、工具能力、产物限制、预览生命周期 |
| 多轮项目自动化 | 第一轮生成结果，后续在同一工作区继续调整 | 同 Session 单活动 Run、对话保持、空闲恢复差异 |
| 连接外部业务系统 | Agent 读取需求，在授权和审批后写入报告 | 凭据范围、批准前零写入、未知结果对账 |
| 多种执行组合 | 应用使用共同的 SDK，选择不同云环境与 Harness | 能力预检、协议兼容性、精确组合的真实验证 |

## 如何决定是否引入控制平面

如果你只需要在自己的终端运行一次 Harness，可以直接使用该 Harness。如果你希望自己实现全部调度、状态持久化、凭据和资源清理，可以直接使用 Sandbox API。

Hexagon 适用于需要把这些生命周期能力作为应用基础设施的场景。引入它同时意味着你需要运行控制平面和数据库，管理自己的 Provider / 模型账户，并监控未完成的云操作。

## 接入前明确这些边界

- **模型协议**：Messages、Chat Completions、Responses 按 Harness 和端点分别支持，不承诺自动转换或 fallback。
- **预览**：用于访问 Session 内运行的 Web 服务，具有授权和过期限制；不提供通用的生产应用发布承诺。
- **状态**：Run 结果、工作区、Harness 对话和进程内存具有不同持久化边界。
- **恢复**：客户端断线可以重新观察原任务；外部写入响应丢失需要对账，不能无条件重试。
- **身份**：你的应用仍需验证业务用户是否有权读取或操作对应任务。控制平面的租户校验不能替代应用业务授权。
- **兼容性**：支持一个 Provider 不代表它支持每个 OCI 镜像、模型协议或网络策略。
